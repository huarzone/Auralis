# Auralis · 映境

**✨ DeepSeek Harness 的自定义主题与模型用量分析插件**

Auralis 复用 DSH 原有的侧栏、会话和设置窗口。你可以换上自己的壁纸，也可以只用「使用分析」：主题和看板各有独立开关。插件使用宿主提供的 React，不需要单独部署网站、数据库或统计服务。

[安装](#安装) · [使用分析](#使用分析) · [外观与设置](#外观与设置) · [数据与隐私](#数据与隐私) · [从源码构建](#从源码构建)

## 安装

| 项目 | 要求 |
| --- | --- |
| 宿主 | DeepSeek Harness，Web 界面 |
| DSH 版本 | `0.2.1-rc.5` 或 `0.2.2-rc.4`（`auralis@0.1.2` 声明的兼容版本） |
| Node.js | `24.14.0` 或更高版本 |

在**运行 DSH 的机器**上准备好 `auralis-0.1.2.tgz`。可以把已有安装包复制过去，也可以按下文从源码打包。若仓库发布了 GitHub Release，请下载附件中的 `.tgz`，而不是 GitHub 自动生成的 *Source code* 压缩包。

在安装包所在目录执行：

```sh
dsh plugin --profile web add ./auralis-0.1.2.tgz
```

`web` 是示例 profile 名称，如有不同请替换。也可以在 DSH **插件管理器**中用该安装包在**宿主机器上的绝对路径**安装并启用 `auralis`。重新打开 Web 页面后，设置中应出现 **Auralis** 页签，侧栏默认出现 **使用分析**。

> **从 Draflow Studio 切换？** 若旧插件仍提供主题和分析，请先停用旧插件，避免两个插件争用同一设置入口。Auralis 可以独立安装，不会导入旧插件的数据。

## 使用分析

打开侧栏的 **使用分析**。例如，想知道「刚才为什么感觉变慢」，可以先选 **15 分钟**，看首字延迟和请求量，再在页面下方按模型、会话或失败状态筛选请求明细。

- **用量**：查看请求数、Token 总量、每分钟请求数（RPM）、每分钟 Token 数（TPM）及缓存命中率；按模型或会话展开用量构成。
- **延迟与失败**：对照首字延迟、总耗时、生成速度，以及失败与重试记录。无法读取的会话会单独提示，不混入统计。
- **时间范围**：15、30、60 分钟窗口每次请求完成后等待 10 秒再刷新，其他窗口等待 60 秒。切到后台会暂停轮询；热力图的日、周、月、年周期可独立选择。

看板只统计 DSH 会话日志中已记录的调用，**不估算费用**。推理 Token 已计入输出，不重复累加。首次打开需汇总历史会话，记录较多时可能比后续刷新慢。

## 外观与设置

在 **设置 → Auralis** 中可预览展开和折叠两种头像入口，并直接调整：

| 区域 | 可以调整的内容 |
| --- | --- |
| 外观与背景 | 天空蓝明暗配色、分区间距、遮罩和毛玻璃；使用内置蓝鲸壁纸，或上传 PNG、JPEG、WebP 图片（最大 8 MiB）。 |
| 个人资料与导航 | 本地头像、昵称和签名；登录后可优先展示账号资料。可独立开关头像设置入口与「插件中心」名称。 |
| 页面与看板 | 自动化任务页透明、设置窗口毛玻璃、侧栏使用分析入口。关闭主题不影响看板。 |

**安装前值得知道：**随包的 [DSH 补丁](./cordis.patch.yml) 默认关闭官方账号界面、消息反馈按钮和模型首次引导，而非关闭身份认证。若要保留这些原生界面，可在 **设置 → Auralis → 官方功能** 中重新开启。手动修改的官方开关写入 DSH profile，卸载 Auralis 不会自动撤销；**「恢复插件默认」也不等同于恢复安装前的宿主配置**。

## 数据与隐私

| 数据 | 存放位置与用途 |
| --- | --- |
| 外观、个人资料、自定义壁纸 | 存在 DSH 宿主的 `<profile>/data/auralis/`，同一 profile 的浏览器共享。偏好文件是 `settings.json`，上传的壁纸单独保存为 `background.bin`。 |
| 看板时间范围和热力图周期 | 记在当前浏览器；初始外观也有浏览器缓存，最终以服务端偏好为准。 |
| 使用分析 | 由插件在宿主侧读取既有会话日志，经 DSH 的 owner 鉴权接口送到同源浏览器绘图。无需第三方分析服务，也不创建独立统计库。 |

安装包不包含用户会话或 profile 数据。**分享看板截图前请检查会话标题、工作目录和错误摘要**：它们有助于排查问题，也可能暴露项目细节。账号资料和账号头像沿用宿主的账号服务，不属于分析数据上报。

## 从源码构建

在项目根目录运行，**无需 `npm install`**：

```sh
npm run build   # 生成 dist/client.js，并内嵌壁纸
npm run check   # 检查服务端与浏览器端语法
npm test        # 运行 Node.js 回归测试
npm pack        # 自动执行 prepack，在当前目录生成 auralis-<版本>.tgz
```

生成的 `.tgz` 是可带到其他机器安装的文件；不需要复制 `node_modules`、浏览器缓存或原机器的 profile。构建过程见 [`scripts/build.mjs`](./scripts/build.mjs)，发布文件清单与兼容版本见 [`package.json`](./package.json)。
